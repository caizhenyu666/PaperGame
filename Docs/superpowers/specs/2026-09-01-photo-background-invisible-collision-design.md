# 照片背景与透明碰撞关卡设计

## 目标

游戏直接展示用户拍摄并拉正后的纸张照片。纸上的横线和旗帜保留在背景图片中，Unity 不再重画平台或旗帜。识别结果只用于创建不可见的地面碰撞体、终点触发器和角色出生点。

## 核心原则

- 照片是唯一的关卡视觉来源。
- 图片与物理对象共用拉正后的像素坐标系。
- Unity 不生成黑色平台、旗杆或红色旗面。
- 识别失败时提示用户修正，不修改用户画出的关卡。
- 照片校正与关卡识别分离，便于分别测试和替换实现。

## 处理流程

```text
原始照片
  → 检测纸张四角
  → 透视校正与横屏旋转
  → 输出校正后的背景图片
  → 在校正图中识别横线、旗帜和左下起始平台
  → 输出统一像素坐标 JSON
  → Unity 显示背景并创建透明碰撞体
```

## 照片拉正

### 自动模式

使用 OpenCV 完成：

1. 缩小图片用于轮廓检测，保留原图用于最终变换。
2. 灰度化、降噪和边缘检测。
3. 查找面积最大的凸四边形纸张轮廓。
4. 将四角排序为左上、右上、右下、左下。
5. 使用透视变换将纸张映射为正视矩形。
6. 若输出为竖屏，则根据旗帜方向或用户确认旋转为横屏。

### 手动兜底

自动检测不到可靠四角时返回 `needs_correction`。界面显示原图和 4 个可拖动角点；用户确认后使用相同的透视变换流程。系统不得猜测缺失边界。

## 输出数据契约

所有坐标均基于校正后图片，原点在左上角，单位为像素。Unity 加载时统一完成 Y 轴翻转和像素到世界单位的换算。

```json
{
  "status": "ready",
  "backgroundImage": "C1Levels/level1-background",
  "canvas": { "width": 1920, "height": 1080 },
  "playerStart": { "x": 220, "y": 890 },
  "platforms": [
    { "x1": 160, "y1": 900, "x2": 520, "y2": 900 }
  ],
  "goalRegion": { "x": 1600, "y": 180, "width": 120, "height": 180 },
  "paperCorners": [
    { "x": 210, "y": 390 },
    { "x": 1450, "y": 410 },
    { "x": 1460, "y": 1210 },
    { "x": 200, "y": 1200 }
  ]
}
```

平台使用端点而不是中心点和宽度，避免再次丢失线段方向。测试阶段只接受近水平线；轻微倾斜的碰撞体按真实角度旋转。

## Unity 运行时

### 背景

- 将校正后的照片加载为单个 Sprite。
- 背景 Sprite 覆盖整个逻辑画布，保持图片宽高比。
- 相机固定显示整个背景，不根据碰撞体或角色重新取景。
- 背景排序层低于角色，不参与碰撞。

### 透明地面

- 每条平台线段生成一个带旋转角度的 `BoxCollider2D`。
- 碰撞厚度使用小型固定物理值，仅保证角色稳定站立。
- 平台对象不添加 `SpriteRenderer`，游戏中完全不可见。

### 透明终点

- `goalRegion` 生成 `BoxCollider2D`，并设置 `isTrigger = true`。
- 不生成旗杆、旗面或任何红色图形。
- 玩家进入区域时沿用现有通关逻辑。

### 角色

- 角色显示在照片上方。
- 出生点位于左下第一条可站立线段的上方。
- 跳跃高度调节只影响角色物理，不修改照片或碰撞体。

## 错误处理

- `PHOTO_INVALID`：图片无法解码或分辨率不足。
- `PAPER_NOT_FOUND`：未检测到可靠的纸张四边形。
- `NEEDS_CORNER_CONFIRMATION`：自动四角置信度不足，需要手动确认。
- `NO_GROUND`：校正后的纸张中未检测到横线。
- `NO_FLAG`：未检测到终点旗帜。
- `MULTIPLE_FLAGS`：检测到多个候选旗帜，需要用户确认。

错误结果必须包含原图中的候选区域，供界面高亮。

## 测试与验收

- 透视校正后，纸张四角分别贴合输出图片四角，误差不超过 3 px。
- 背景图片宽高比与 JSON `canvas` 一致。
- 平台端点映射到 Unity 后，与背景中横线位置重合。
- 地面和终点对象没有 `SpriteRenderer`。
- 角色可站在照片横线上，并能触发照片旗帜对应的终点区域。
- 改变 Game View 宽高比时，背景、碰撞体和角色保持对齐。
- 自动找纸失败时进入四角确认流程，不生成猜测关卡。

## 本阶段范围

本阶段先实现一张样本图片的本地拉正、背景加载和透明物理关卡。相机拍摄 UI、服务端上传接口和批量照片识别不在本次实现范围内。
