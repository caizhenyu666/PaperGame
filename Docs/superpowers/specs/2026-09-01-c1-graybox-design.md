# C1：Unity 游戏灰盒设计

## 目标

在 Unity 2022.3 WebGL 项目中提供一个完全离线、无需服务端的可游玩灰盒关卡。玩家用键盘控制角色跑、跳、落地；触碰唯一旗帜后完成关卡。

## 范围

- 输入：内置 mock `LevelDefinition`，包含多个水平平台与唯一目标旗帜。
- 控制：A/D 或左右方向键移动，空格跳跃。
- 表现：蓝色方块角色、深色地面、红色旗帜；不接入图片、网络、正式 UI 或相机拍摄。
- 目标平台：Unity WebGL；运行期也可在编辑器 Play Mode 验证。

## 架构

`GameBootstrap` 为场景唯一入口。它构造 mock 关卡，并通过工厂方法创建角色、静态地面和目标旗帜，随后绑定跟随镜头。

`PlayerController2D` 管理输入、水平速度、接地判断和单次跳跃。角色使用 `Rigidbody2D` 与 `BoxCollider2D`；接地状态由接触法线判断，避免空中重复跳跃。

`GoalFlag` 持有一次性完成状态。检测到玩家碰撞体进入后，通知 `GameBootstrap`；后者冻结角色控制、显示轻量完成提示，并忽略后续触发。

`SimpleFollowCamera` 仅跟随玩家 X 轴，Y 轴固定，以保持地面与目标在合理视野内。

## 数据流

1. 场景启动时，`GameBootstrap` 创建 mock 关卡定义。
2. 定义映射为带 `BoxCollider2D` 的地面和带 trigger collider 的唯一旗帜。
3. 玩家输入驱动刚体移动和跳跃；物理系统处理落地。
4. 玩家进入旗帜触发区，游戏进入完成状态且只能结算一次。

## 错误处理与边界

- mock 关卡必须至少有一个平台和一个旗帜；非法定义在启动时记录错误并不创建游戏。
- 角色仅在接地时接受跳跃输入。
- 完成后角色停止响应移动和跳跃输入。
- C1 不负责 JSON 文件读取、远端资源、精灵表切帧或服务端可玩性判定；这些归属 C2/C3 及后续工作包。

## 验收与测试

- 编辑器 Play Mode：角色可在地面上左右移动、跳上相邻平台并稳定落地。
- 编辑器 Play Mode：空中反复按空格不产生二段跳。
- 编辑器 Play Mode：触碰红旗显示完成提示，重复触碰不会重复结算。
- WebGL 构建后可在浏览器用相同键位完成关卡。
