# C1 固定镜头与角色动画设计

## 目标

调整现有 C1 灰盒，使整个关卡始终完整呈现在同一个固定镜头中，并使用工程内的 `idle`、`run`、`jump` 三套精灵集替换蓝色方块角色，实现与物理状态同步的角色动画。

## 范围

- 移除游戏过程中的镜头跟随。
- 在关卡生成时一次性计算镜头中心和正交尺寸，完整容纳平台、出生点与终点。
- 将 `idle.png` 和 `jump.png` 的棋盘格背景处理为透明通道，不保留原始非透明版本。
- 将三套精灵集切分为动画帧。
- 静止时播放 Idle，水平移动时播放 Run，离地时播放 Jump。
- 向左移动时翻转角色画面。
- 保留现有移动、跳跃、碰撞和终点结算规则。

不在本次范围内：关卡美术替换、背景设计、镜头运镜、音效、移动端输入和 GitHub 推送。

## 架构

### 固定镜头

`C1GameBootstrap` 在生成关卡后，根据平台边界、玩家出生点和终点边界计算场景包围盒。相机定位到包围盒中心，并结合当前屏幕宽高比设置足以容纳包围盒的 `orthographicSize`，再加入少量安全边距。

该计算只在构建或重新开始关卡时执行。游戏运行期间相机不再挂载或调用 `C1FollowCamera`，角色移动不会改变镜头位置。

### 精灵资源

三套角色图片作为可切分的精灵资源导入。`idle.png` 和 `jump.png` 直接改为带 Alpha 通道的透明 PNG；`run.png` 使用已有透明通道。切帧结果保持统一画布和锚点，避免动画切换时角色位置抖动。

角色视觉尺寸独立于物理碰撞体。`BoxCollider2D` 和 `Rigidbody2D` 继续挂在玩家根对象上，精灵渲染器放在子对象中，因此不同姿态不会改变碰撞判定。

### 动画状态

新增 `C1CharacterAnimator2D`，只负责视觉状态与帧播放：

- `Jump`：角色未接地时优先播放。
- `Run`：角色接地且水平速度绝对值超过阈值时播放。
- `Idle`：角色接地且基本静止时播放。
- 角色完成关卡后停止状态变化并显示稳定的 Idle 画面。
- 水平速度为负时设置 `SpriteRenderer.flipX = true`，为正时恢复向右。

状态来自 `C1PlayerController2D` 的接地状态和 `Rigidbody2D.velocity`，动画组件不修改物理数据。

## 数据流

1. `C1GameBootstrap` 生成平台、玩家和终点。
2. Bootstrap 为玩家创建独立视觉子对象并配置三组动画帧。
3. Bootstrap 计算一次场景边界并配置固定相机。
4. `C1PlayerController2D` 按输入更新物理状态。
5. `C1CharacterAnimator2D` 每帧读取接地状态与速度，选择状态、推进帧并处理朝向。
6. 玩家到达终点后，现有完成逻辑冻结物理，HUD 显示重新开始按钮。

## 异常与降级

- 任一动画资源缺失时记录明确错误，并使用现有纯色占位精灵，确保关卡仍可运行。
- 动画帧数组为空时不推进帧，避免索引越界。
- 镜头边界无效时使用预设中心和尺寸，避免黑屏或数值异常。

## 测试与验收

自动测试覆盖：

- 镜头配置后不包含 `C1FollowCamera`，且关卡边界位于相机视野内。
- 接地静止选择 Idle。
- 接地移动选择 Run。
- 离地选择 Jump，并具有最高优先级。
- 左右速度正确控制精灵翻转。
- 动画帧可循环推进，空帧数组安全降级。
- 现有移动、跳跃、终点和 HUD 测试继续通过。

WebGL 验收覆盖：

- 初始画面可同时看到完整平台路径、玩家和终点。
- 玩家移动时镜头保持不动。
- Idle、Run、Jump 动画随状态切换。
- 左右移动朝向正确。
- 到达终点后仍正常结算并可重新开始。
