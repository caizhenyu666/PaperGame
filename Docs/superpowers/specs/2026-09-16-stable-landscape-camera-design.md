# PaperGame 固定横屏与拍照界面设计

## 背景与根因

PaperGame 的移动端 WebGL 页面使用 CSS 在物理竖屏时将 `#unity-container` 旋转 90°，从而让游戏内容始终以横屏形式显示。当前实现仍在 `resize` 和 `ResizeObserver` 回调中根据 DOM 尺寸重设 Unity Canvas 的 `width`、`height`。手机旋转期间，浏览器会连续发布多个中间视口尺寸；每次修改 Canvas 尺寸都会清空并重建 WebGL 渲染缓冲，因此用户会看到闪烁。

拍照覆盖层由 `PaperGamePhotoCapture.jslib` 直接添加到 `document.body`，使用物理视口的 `100vw × 100vh` 排版，没有复用游戏的横屏坐标系。设备横竖屏切换时，覆盖层会重新排版；取景框还同时使用固定宽高与独立的 `max-width`、`max-height`，在小屏上可能被单轴压缩，导致视觉比例和实际裁剪范围变化。

## 目标

- 游戏从横屏转为竖屏或从竖屏转为横屏时，画面始终保持横屏，不出现 WebGL 缓冲重建造成的闪烁。
- Unity 游戏和拍照覆盖层共享稳定的横屏逻辑坐标系，设备旋转只改变外层变换，不触发内部重新排版。
- 拍照取景框始终保持相同宽高比、样式和相对位置；小屏只能整体等比缩小。
- 视频预览铺满横屏舞台，输出照片只包含取景框内的区域，裁剪结果与视觉框一致。
- 拍照界面提供关闭按钮。点击后立即停止摄像头、移除覆盖层并返回原页面，不发送错误或取消回调。
- 快门采用接近 iPhone 相机的白色双圆样式，不显示文字。
- 继续保留 PWA Manifest 的横屏偏好，同时保证 iOS 未执行系统方向锁定时仍有可用的页面级兜底。

## 非目标

- 不依赖 `screen.orientation.lock()` 作为主方案。
- 不修改 Unity 场景、游戏相机取景算法或 HUD 布局。
- 不修改照片上传、识别和存储流程。
- 不实现前后摄像头切换、变焦、闪光灯或拍后确认页面。
- 不承诺由网页控制 iOS 系统界面的物理方向；只保证应用内容的显示方向与稳定性。

## 方案比较

### 方案 A：统一固定横屏舞台（采用）

将物理视口作为外层容器，将 Unity 与拍照界面都放在稳定的横屏逻辑舞台中。设备方向变化时仅更新舞台的 CSS 几何变换；Unity 的渲染缓冲保持不变。该方案同时解决 WebGL 闪烁、拍照布局变化和触控坐标一致性问题。

### 方案 B：依赖 Screen Orientation API

进入全屏后调用 `screen.orientation.lock("landscape")`。实现简单，但 iPhone、iPad 多任务模式及不同 Safari 版本的支持不一致，Promise 可能被拒绝，无法满足稳定性要求。

### 方案 C：旋转期间显示上一帧遮罩

旋转开始时复制 Canvas 画面并临时覆盖，旋转结束后恢复。它只能遮挡闪烁，不能消除渲染缓冲重建，也不能自动解决拍照界面的布局与裁剪问题，因此不采用。

## 设计

### 固定横屏舞台

页面维护一个横屏逻辑尺寸：长边为逻辑宽度，短边为逻辑高度。横屏物理视口直接显示该舞台；竖屏物理视口对同一舞台旋转 90° 后显示。方向变化只更新舞台的 `width`、`height`、位置和 `transform`，不根据旋转过程中的中间尺寸反复修改 Unity Canvas 的渲染缓冲。

Unity Canvas 的渲染分辨率仅在初始化或稳定的非方向尺寸变化时更新。方向切换期间长短边互换不视为新的逻辑尺寸，因此不清空 WebGL 缓冲。浏览器地址栏或安全区域引发的小幅视口变化由外层舞台缩放吸收。

现有触控坐标归一化继续以舞台的实际包围盒为输入，在竖屏变换下将事件坐标逆变换回横屏逻辑坐标。鼠标与触摸事件使用同一套方向状态，避免 CSS 媒体查询和 JavaScript 在旋转中间帧判断不一致。

### PWA 方向策略

`manifest.json` 继续声明 `"orientation": "landscape"`，让支持该 Manifest 成员的主屏幕 Web App 优先以横屏启动。页面不假设该声明一定被 iOS 执行，也不以运行时 `screen.orientation.lock()` 的成功作为功能前提。

固定横屏舞台是兼容性兜底：系统允许物理竖屏时，应用内容仍保持横屏。方向锁定 API 即使缺失或拒绝，也不会改变页面行为。

### 拍照覆盖层

拍照覆盖层使用独立的最高层横屏舞台，其尺寸与方向算法和 Unity 舞台一致。这样相机打开期间无需显示或重排 Unity 内容，且手机横竖屏切换时，视频、取景框和操作按钮作为一个整体旋转。

视频元素以 `object-fit: cover` 铺满拍照舞台。取景框保持固定宽高比；默认视觉尺寸以横屏短边为约束计算，空间不足时对宽高同时乘以同一个缩放系数。不得分别限制宽度和高度，以免改变比例。

拍照时读取视频与取景框的最终包围盒，根据 `object-fit: cover` 的绘制比例和偏移，将框内区域映射回视频原始像素。坐标映射只依赖拍照舞台内部布局，不依赖物理设备方向。

### 操作按钮

- 关闭按钮位于横屏舞台左上角的安全区域内，使用半透明深色圆形底和白色“×”。点击后停止所有 MediaStream Track，移除覆盖层与临时样式，不发送错误消息。
- 快门位于横屏舞台右侧垂直居中位置，使用白色外圈和白色实心内圈，不包含文字。
- 快门按下时内圈轻微缩小，提供即时触觉感受对应的视觉反馈。
- 拍照处理中禁用重复点击，并通过透明度或按压状态表达忙碌；不将按钮文本改为省略号或“重试”。
- 拍照失败时恢复快门可点击状态，并沿用现有错误回调或状态提示。

### 生命周期与错误处理

关闭、拍照成功、相机权限失败和视频加载失败都必须走同一个幂等清理函数。清理函数负责：

1. 停止所有摄像头 Track。
2. 清空视频的 `srcObject`。
3. 移除方向与视口监听器。
4. 移除拍照覆盖层和本次创建的样式节点。

权限拒绝或设备不支持摄像头时，先完成清理，再向 Unity 发送原有错误信息。用户主动关闭不属于错误，不发送 `ReceivePhotoError`。

## 测试与验收

### 自动化测试

- WebGL 模板测试验证横屏舞台逻辑不会在普通方向切换中重设 Canvas 渲染尺寸。
- 模板测试验证 Manifest 仍声明 `orientation: landscape`。
- 拍照桥接静态测试验证存在关闭按钮、无文本双圆快门、统一清理逻辑和固定比例取景框。
- 拍照桥接测试验证取景框使用等比缩放，不允许独立 `max-width` 与 `max-height` 改变比例。
- 运行全部 EditMode 测试，确认现有页面模板、照片解析和游戏逻辑无回归。

### 真机验收

在 iPhone Safari 与“添加到主屏幕”的 Web App 中分别验证：

- 游戏运行时连续执行横屏、竖屏、反向横屏切换，画面不黑屏、不白闪、不短暂拉伸，内容始终为横屏。
- 每个方向下触摸按钮的位置与视觉位置一致。
- 打开相机后执行相同旋转，取景框尺寸、比例、样式及相对位置不变。
- 取景框内同一目标的构图范围不因横竖屏切换而改变。
- 快门无文字，外观为白色双圆；连续点击不会重复提交。
- 点击“×”立即熄灭摄像头指示并返回原页面，不显示错误提示。
- 拍照输出的宽高比与取景框一致，边缘内容与预览框一致。

## 兼容性边界

iOS 对 Web App Manifest 的横屏偏好和 Screen Orientation API 的执行会随系统版本、全屏状态及 iPad 多任务模式变化。验收以页面内固定横屏体验为准，不以操作系统是否真正阻止物理方向变化为准。
