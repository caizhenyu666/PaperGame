# 首页与关卡 UI 生命周期设计

## 背景与目标

当前启动流程会同时创建关卡、首页、角色创建页和游戏 HUD。这使首页与关卡
运行态相互耦合，也让未进入游戏的物理对象、相机和输入控件提前存在。

本次调整的目标如下：

- 将首页和游戏运行态拆分为 `Home`、`Game` 两个 Unity 场景。
- 仅在用户点击「创建主角」后创建角色创建界面；创建界面显示期间隐藏首页。
- `Game` 作为唯一的通用关卡场景，根据关卡 ID 加载 JSON 与资源并动态创建关卡。
- 主界面的大底图在任意分辨率下等比覆盖屏幕，不拉伸、不留边。

## 场景职责

### `Home` 场景

`Home` 只负责创建首页 Canvas、首页预制体和 EventSystem。启动后仅显示首页，
不创建角色创建页、玩家、关卡背景、物理碰撞体、相机控制或游戏 HUD。

点击「创建主角」后，由首页控制器实例化角色创建界面，并立即隐藏首页。
角色创建界面的返回操作销毁该实例并重新显示首页。角色数据仍由既有角色库
持久化，因此重复进入不依赖保留上一次的 UI 实例。

点击「开始游戏」时，首页控制器保存本次要进入的关卡 ID，并加载 `Game` 场景。

### `Game` 场景

`Game` 是唯一的游戏场景，不为每一个关卡新增 `.unity` 文件。场景加载后，
`C1GameBootstrap` 读取待进入的关卡 ID，加载对应 JSON、背景和角色资源，再创建
关卡背景、物理碰撞体、玩家、相机、游戏 HUD 和移动控制。

完成、失败和主动返回首页都使用同一出口：清理游戏运行对象、卸载 `Game` 场景，
并加载 `Home` 场景。失败后不再直接在当前场景重复执行 `Build`。

## UI 生命周期与数据流

```text
启动
  -> Home：创建首页
  -> 点击「创建主角」：隐藏首页，创建角色创建页
  -> 返回首页：销毁角色创建页，显示首页
  -> 点击「开始游戏」：保存关卡 ID，加载 Game
  -> Game：根据关卡 ID 创建关卡
  -> 完成／失败／返回：首页场景
```

关卡 ID 由一个小型、无场景依赖的会话对象保存。它只保存本次运行所需的关卡 ID，
不保存 UI 对象引用。`Game` 未取得有效 ID 时回退到默认关卡，并输出明确警告，避免
场景启动失败。

## 分辨率适配

首页 Canvas 使用 `Scale With Screen Size`，参考分辨率为 `1280 × 720`。标题、按钮和
教程卡继续使用归一化锚点布局，并限制在画面的中央安全区，以适应超宽与较高屏幕。

首页背景采用 Cover（封面）策略：以 `max(屏幕宽／图片宽, 屏幕高／图片高)` 等比缩放，
直到图像覆盖整个屏幕。超出屏幕的边缘被裁切；图片本身不被拉伸，也不会产生留边。
背景资源应把关键绘制内容放在中央安全区，四周仅放可裁切的装饰。

角色创建页与游戏 HUD 使用同一 Canvas 缩放约定；游戏内的关卡背景仍由世界坐标和相机
取景计算决定，不与首页 Cover 背景混用。

## 组件边界

- `HomeBootstrap`：创建首页 Canvas 和首页预制体，协调首页与角色创建页的切换。
- `C1CharacterSelection`：只管理已经创建的角色创建页及角色选择／创建，不负责启动时
  创建首页或暂停关卡玩家。
- `C1GameSession`：保存待加载关卡 ID，提供默认关卡回退。
- `C1GameBootstrap`：仅在 `Game` 场景创建和清理关卡运行对象。
- 首页背景适配组件：仅根据父 RectTransform 计算 Cover 尺寸，不影响前景控件布局。

## 验收与测试

- 进入 `Home` 后不存在角色创建页、玩家、关卡根节点和游戏 HUD。
- 点击「创建主角」后才产生角色创建页，且首页不可见；返回后角色创建页已销毁、首页可见。
- 点击「开始游戏」后加载 `Game`，并根据会话中的关卡 ID 创建对应关卡。
- 完成、失败与主动返回均回到 `Home`。
- 在 16:9、超宽和竖屏尺寸下，首页背景覆盖全屏、保持原始宽高比且没有留边；前景按钮仍在
  中央安全区可点击。
- 为场景路由、延迟创建和 Cover 尺寸计算补充 EditMode 测试；现有相关测试同步调整。

## 不在本次范围内

- 不新增每关一个 Unity 场景。
- 不改变关卡 JSON 格式、角色生成服务协议或角色资源格式。
- 不重绘首页背景美术；只定义其导入与适配行为。
