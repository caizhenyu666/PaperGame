# 移动端 WebGL 触控设计

> 已合并至 `2026-09-02-mobile-webgl-play-and-capture-design.md`，后续以合并规格为准。

## 目标

让当前照片关卡可直接在手机浏览器中横屏游玩，同时保留桌面端键盘操作与试玩跳跃高度调节区。

## 方案选择

- 采用：Unity Canvas 触控按钮。左右移动和跳跃直接调用角色控制器，WebGL、Android 与 iOS 可复用。
- 不采用：HTML/JavaScript 覆盖按钮。它需要额外维护 JS 到 Unity 的消息桥接，且不适用于原生包。
- 暂不采用：直接制作 APK/IPA。安装、签名和分发成本高，不符合当前快速分享试玩的阶段目标。

## 交互设计

- 左下角放置半透明圆角感的“左”“右”两个大按钮，支持按住连续移动和多点触控。
- 右下角放置半透明“跳跃”按钮，按下立即尝试跳跃。
- 键盘 `A/D`、方向键和空格继续有效；键盘有输入时优先使用键盘，否则使用触控方向。
- 触控松开、手指移出按钮或控件禁用时立即清空该方向，避免角色持续移动。
- 触屏设备竖屏时显示“请旋转手机横屏游玩”的遮罩提示；横屏时隐藏。
- 触控控件只在触屏/移动设备显示；EditMode 测试仍可直接创建并调用组件。

## 组件边界

- `C1PlayerController2D`：保存触控水平输入，并在现有 `Update` 中与键盘输入合并。
- `C1MobileControls`：维护左右按钮按压状态，向玩家发送方向值和跳跃请求。
- `C1TouchDirectionButton`：把 PointerDown、PointerUp、PointerExit 转发给移动控制器。
- `C1TouchJumpButton`：PointerDown 时转发跳跃请求。
- `C1GameBootstrap`：在 HUD 下生成控件、布局和横屏提示，不改变照片背景或物理坐标。

## 适配与部署

- 沿用 Unity 默认 WebGL 移动模板的 viewport 和全屏 Canvas 规则。
- HUD 使用 `Scale With Screen Size`，触控按钮锚定屏幕底部两侧并尊重固定边距。
- WebGL 服务器必须为 `.gz` 文件返回正确的 `Content-Encoding: gzip`。
- 局域网试玩时服务器监听 `0.0.0.0`，手机通过电脑局域网 IP 访问。

## 验收标准

- 按住左/右按钮时角色持续向对应方向移动，松手立即停止水平输入。
- 跳跃按钮和空格键均能触发跳跃，不能绕过已有落地判断和二段跳限制。
- 桌面键盘输入不受触控逻辑影响。
- 横屏下控件不遮挡玩家主要活动区域；竖屏显示旋转提示。
- Unity EditMode 全量测试通过，WebGL 构建成功并在移动视口显示完整画面。
