# 儿童绘本风试玩 UI 设计

## 目标与范围

为《纸上游戏机》制作面向 5–8 岁儿童、**仅手机横屏**使用的试玩闭环 UI。该轮只覆盖本地试玩体验，不接入服务端，不改变关卡、跑跳、拍照或 WebGL 构建逻辑。

交付页面为首页、玩法引导、游戏内 HUD、成功页和重试页。拍摄入口只显示“即将开放”，不发起上传请求。

## 视觉方向

以儿童绘本插画为主：奶油色纸张底、柔和水粉笔触、圆角大色块、手绘纹理和清晰的大字。背景保留纸上横线平台、火柴人角色与红旗终点，强化“把画变成游戏”的核心概念。

主色为天蓝、叶绿、珊瑚红和向日葵黄；正文使用高对比深灰。装饰只用于营造温暖氛围，不能遮挡按钮、文字、关卡或触控区域。

## 页面与流程

1. 启动时进入首页。主按钮“开始试玩”进入玩法引导；次按钮“拍摄我的关卡”显示不可交互的“即将开放”状态。
2. 玩法引导为三张全屏卡片，顺序为“按住左右移动”“按跳跃跨过障碍”“碰到红旗就赢啦”。每张卡片有单一插画、短句和页码点；最后一张的按钮为“开始玩吧”。
3. 进入游戏后只显示必要 HUD：左下左/右移动按钮、右下黄色跳跃按钮、左上暂停按钮。现有拍照、状态、预览和跳跃高度调试面板不进入正式试玩 HUD。
4. 角色触碰旗帜后显示成功页：“你到终点啦！”、“再玩一次”主按钮，并用红旗、彩纸和星星装饰。
5. 角色掉出关卡后显示重试页：“再试一次吧”，辅助提示“跳高一点，越过障碍”，主按钮“再试一次”。页面不用“失败”字眼。

首次试玩完整走引导；用户可在暂停菜单中重新查看引导。除非重置本地偏好，否则后续从首页点击“开始试玩”直接进入游戏。

## Unity 组件边界

- `PaperGameUiTheme`：保存颜色、字体、按钮尺寸和间距等主题 token，供所有页面共享。
- `PaperGameHome`：首页呈现和开始/拍摄入口事件。
- `PaperGameTutorial`：三页引导的状态、前进与完成回调。
- `PaperGameHud`：移动、跳跃和暂停输入；只负责 UI，不持有角色物理逻辑。
- `PaperGameResultPanel`：参数化呈现成功或重试状态，并触发现有重新构建关卡回调。
- `PaperGameUiFlow`：唯一的页面切换入口，维护 `Home`、`Tutorial`、`Playing`、`Completed`、`Retry` 状态，订阅现有角色完成和掉落事件。

所有页面预制体在编辑器中生成并保存为独立 `.prefab`；运行时实例化到一个固定的屏幕空间 Canvas。游戏逻辑通过公开 C# 事件或回调驱动页面转换，UI 不直接查询或改写 `C1PlayerController2D` 的物理状态。

## 资源与导入

导出一组 PNG 元素：纸张背景、云朵、草地、花朵、红旗、成功彩纸、卡片框、五类按钮底图（主、次、方向、跳跃、暂停）和对应图标。需要拉伸的框、按钮底图和纸张纹理使用九宫格 Sprite；独立插画维持原比例。

资产保存到 `Assets/Art/UI/PictureBook/`，预制体保存到 `Assets/Prefabs/UI/`，主题资产保存到 `Assets/UI/`。元素使用明确英文文件名，避免覆盖现有游戏资源。

## 横屏与可访问性

- HUD、页面与按钮按 16:9 横屏基准设计，Canvas 使用 `Scale With Screen Size`。
- 竖屏时继续使用现有“请将手机旋转为横屏”遮罩；遮罩显示时不得响应游戏输入。
- 可点击区域最小为 96×96 参考像素；按钮之间至少保留 24 参考像素间距。
- 文案单行优先，字号不得小于 28 参考像素；关键操作同时使用图标和文字/视觉指向，不能只依赖颜色区分。

## 状态与异常处理

- 未完成教程时，主页“开始试玩”总是先进入教程；完成后持久化一个本地布尔值。
- 未接入服务端前，拍摄入口无网络调用，明确展示“即将开放”。
- 关卡构建失败或未能找到角色时，回退到现有可试玩默认关卡，并记录 Unity 警告；不显示空白界面。
- 重新开始时销毁旧 UI 实例或重置状态，确保不会出现重复 Canvas、重复事件监听或叠层结果页。

## 验收与测试

- EditMode 测试验证：默认显示首页；教程为 3 页；完成教程后进入试玩；成功/掉落分别只打开对应结果页；重新开始仅触发一次关卡重建。
- 在 16:9 和更窄的横屏分辨率下检查按钮不越界、不互相遮挡；竖屏遮罩出现时 HUD 不可操作。
- WebGL 手机验收：儿童能从首页理解主按钮，能完成左右移动、跳跃、到达红旗和再次开始的循环。

## 非目标

本轮不实现服务端上传、照片识别、账户、成就、作品册、音效、动画制作或多关卡选择。它们会在试玩 UI 稳定后另行设计。
