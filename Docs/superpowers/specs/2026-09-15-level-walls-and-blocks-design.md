# 纸上关卡墙体与实体图形识别设计

## 背景

当前关卡解析仅输出近水平线段作为 `platforms`。起点圆圈和终点旗帜虽然会单独识别，但它们的笔画仍可能进入直线或闭合图形候选。降低短线识别门槛后，旗杆被误判成墙、圆圈局部被误判成短平台的概率会进一步增加。

本次改造需要满足以下目标：

- 起点圆圈和终点旗帜必须保留唯一性门禁，但不参与平台、墙或实体图形识别。
- 近水平线识别为平台，近竖直线识别为具有阻挡作用的墙。
- 单线碰撞体沿用当前固定厚度。
- 空心闭合轮廓和实心多边形均识别为实体图形，并按外接矩形的实际宽高生成碰撞体。
- 支持归一化画布上约 55 px 以上的短平台和短墙，同时避免将文字、污渍和标记笔画识别为碰撞物。
- 旧关卡数据继续可用，不要求重新生成。

## 方案选择

采用显式三类碰撞物：

- `platforms`：近水平线段。
- `walls`：近竖直线段。
- `blocks`：闭合轮廓或实心多边形的外接矩形。

不采用「所有几何都放入 `platforms`」的方案，因为 C 端需要根据角度猜测语义，协议难以验证和扩展。暂不引入统一多态 `colliders` 协议，因为当前只有线段和矩形两种碰撞表示，引入多态会扩大迁移与兼容成本。

## 服务端识别流程

### 1. 标记优先识别

在平台、墙和实体图形分类前，先识别起点圆圈与终点旗帜。仍要求：

- 起点圆圈恰好 1 个。
- 终点旗帜恰好 1 个。
- 缺失或存在多个候选时，生成关卡失败。

标记检测结果形成排除区域。排除采用候选几何重叠判断，不直接擦除整块原图，避免旗帜下方的平台因旗杆与平台相交而被截断。

候选处理优先级为：

1. 起点圆圈与终点旗帜。
2. 实体图形 `blocks`。
3. 平台 `platforms` 与墙 `walls`。

若一条短线的主体位于圆圈或旗帜区域内，则丢弃该线。穿过标记区域但大部分位于区域外的长平台予以保留。

### 2. 线段分类

线段统一经过墨迹连续性、角度、长度、边界和标记重叠校验，再按方向分类：

- 与水平方向夹角不超过 6°：平台。
- 与竖直方向夹角不超过 6°：墙。
- 其他角度：本版本忽略，不识别为斜坡。

归一化画布为 900 × 560 px。线段最小长度取 `max(55 px, 短边的 10%)`，当前画布下为 56 px。

长度小于 110 px 的候选属于短线，除通用规则外还必须满足：

- 长宽比不小于 4.5。
- 拟合角度满足对应方向要求。
- 中心线附近的深色墨迹连续覆盖率不低于 70%。
- 不与起点圆圈或终点旗帜主体显著重叠。
- 不位于纸张边缘安全区内。

长度不小于 110 px 的候选沿用现有平台识别规则。

### 3. 实体图形识别

实体图形同时支持空心轮廓和实心多边形：

- 空心图形通过闭合轮廓及内外轮廓关系识别。
- 实心图形通过连通区域、面积和轮廓识别。
- 三角形、四边形及其他多边形统一输出其轴对齐外接矩形。

实体图形必须满足最小宽高、最小面积、闭合度和边界安全区要求。圆圈与旗帜候选区域不参与实体图形输出。

实体图形可能同时产生多条水平或竖直边线。确定 `block` 后，主体位于其外接矩形内部或贴合边界的重复平台、墙候选予以删除，避免同一笔画生成多个重叠碰撞体。

## JSON 协议

在现有 `Level` 中增加 2 个可选数组：

```json
{
  "platforms": [
    {
      "id": "platform_001",
      "start": { "x": 120, "y": 300 },
      "end": { "x": 260, "y": 300 },
      "confidence": 0.91
    }
  ],
  "walls": [
    {
      "id": "wall_001",
      "start": { "x": 420, "y": 180 },
      "end": { "x": 420, "y": 360 },
      "confidence": 0.90
    }
  ],
  "blocks": [
    {
      "id": "block_001",
      "region": {
        "x": 520,
        "y": 280,
        "width": 100,
        "height": 70,
        "confidence": 0.88
      }
    }
  ]
}
```

`walls` 和 `blocks` 默认是空数组，属于向后兼容的可选扩展。协议仍使用 `schemaVersion: "1.0"`，旧 C 端会忽略新增字段，新 C 端读取缺失字段时按空数组处理。

平台仍要求至少存在 1 条；墙和实体图形不是生成成功的必要条件。

## Unity C 端

`C1LevelDefinition` 增加墙和实体图形定义：

- `Walls`：线段数组。
- `Blocks`：矩形区域数组。

加载 API JSON 时：

- 缺失的 `walls`、`blocks` 转为空数组。
- 校验所有端点与矩形均位于画布内。
- 墙线段必须以竖直方向为主，平台必须以水平方向为主。

生成关卡时：

- 平台和墙均创建静态 `BoxCollider2D`，线段方向决定旋转角度，厚度使用现有 `GroundThickness`。
- 实体图形使用外接矩形中心作为位置，以实际宽高创建不旋转的静态 `BoxCollider2D`。
- 墙和实体图形只产生普通物理阻挡，不触发死亡或关卡失败。
- 背景图继续显示原始手绘内容，碰撞体保持不可见。

## 缓存与兼容

识别算法输出发生变化后，将任务 ID 的算法盐从 `explicit-markers-v2` 升级到 `explicit-markers-v3`。同一图片重新上传时会生成新的任务 ID，不会复用缺少短平台、墙和实体图形的旧结果。

已保存到本地的旧关卡仍可读取，其 `walls` 和 `blocks` 按空数组处理。无需迁移本地文件。

## 错误处理

- 起点或终点缺失、重复：维持现有生成失败响应。
- 只识别到墙或实体图形、没有任何平台：维持 `NO_PLATFORM_DETECTED`。
- 可疑短线、非闭合图形或斜线：忽略该候选，不阻断整个关卡生成。
- 几何越界或重复：进入现有几何复核流程，不发布无效关卡。

## 测试策略

服务端测试覆盖：

- 圆圈不输出为平台、墙或实体图形。
- 旗杆不输出为墙，旗面不输出为实体图形。
- 与旗杆相交的长平台仍完整保留。
- 55–109 px 的有效短横线输出为平台。
- 55–109 px 的有效短竖线输出为墙。
- 短文字笔画、污渍和纸张边缘不会成为碰撞物。
- 空心矩形、实心矩形及其他空心/实心多边形输出正确外接矩形。
- 实体图形边线不会重复输出为平台或墙。
- 实拍图片回归包含短平台、墙、空心图形和实心图形。
- 缓存盐升级后不复用 v2 任务结果。

Unity EditMode 测试覆盖：

- 新协议正确解析平台、墙和实体图形。
- 旧协议缺少新增字段时仍能加载。
- 墙生成固定厚度的竖直碰撞体。
- 线段沿用固定厚度，实体图形使用实际宽高。
- 墙与实体图形不会生成伤害或失败触发器。

## 不在本次范围

- 斜坡和任意角度线段。
- 按多边形原始轮廓生成 `PolygonCollider2D`。
- 圆形碰撞体或动态物体。
- 墙跳、攀爬、破坏和伤害机制。
- 对关卡可达性或可玩性的判断。
