# 草图保真关卡转换与测试跳跃调节设计

## 目标

将用户拍摄的横屏草图等比例转换为 Unity 关卡 JSON。转换过程保留每条线段的相对位置和长度，不为了可玩性压缩、重排或补画平台。关卡不可通关时，系统生成 JSON，并明确提示用户应修改的纸面区域。

本设计还在测试阶段提供可调的跳跃高度。该调节仅影响当前试玩，不回写草图坐标或生成的关卡 JSON。

## 已确认的产品规则

- 角色从左下第一段地面出发，目标是右上旗帜。
- 草图已经是横屏，不进行旋转。
- 平台视觉和碰撞厚度均为 `0.08` 个游戏单位。
- 坐标映射保持 X、Y 同一缩放比例。
- 不可玩不是转换失败；系统必须产出关卡，并返回 `needs_fix` 诊断。

## 数据流

```text
草图照片
  → 纸张检测、透视校正、方向确认
  → 线段与旗帜检测
  → 等比例坐标映射
  → level.json + analysis.json
  → Unity 构建关卡
  → 当前跳跃高度下的可达性校验与纸面修改提示
```

## 坐标转换契约

### 运行时画布与取景

运行时 JSON 必须显式保存 `canvas`。`canvas.width` 固定为 `32.0`，`canvas.height` 由纸张宽高比推导。相机只根据该矩形及固定边距取景，不能再以平台、角色或旗帜的包围盒自动缩放。

平台、角色和旗帜都使用同一套纸张坐标。`goal` 除触发点外，还必须保存旗杆与旗面的本地尺寸；Unity 按这些尺寸绘制，不能继续使用固定的 `2.8` 高旗杆和 `1.2 × 0.75` 红色旗面。

草图在画布内的留白是几何的一部分，必须在游戏画面中保留。

### 标准画布

逻辑画布宽度固定为 `32.0` 个游戏单位。高度由校正后纸张长宽比决定，禁止分别缩放 X 与 Y。

本图纸张有效区域约为 `(206, 401)` 至 `(1451, 1211)` 像素，宽高比约为 `1.537`。因此画布为 `32.0 × 20.82`，缩放系数约为 `0.02570` 个游戏单位/像素。

映射公式如下，其中 `(u, v)` 为透视校正后的像素坐标：

```text
x = (u - 206) × 0.02570
y = (1211 - v) × 0.02570
```

实际运行时不得依赖上述固定像素值，而应以检测得到的纸张四边和输出画布宽度计算相同公式。

### 识别与输出规则

- 只把纸张内的深色、近水平线段识别为平台；光照阴影、桌面、浏览器边框均不得参与。
- 平台 `x`、`y` 表示线段中心；`width` 是端点距离；`height` 固定为 `0.08`。
- 旗杆与三角旗共同确定唯一终点。`goalPosition` 取旗杆底部与其所在平台的接触点。
- 不得合并视觉上分开的线段，不得延长线段以填平间隙。
- 检测置信度不足时返回 `needs_review`，保留候选坐标和待用户确认区域；不得猜测替换。

## 分析结果 JSON

解析服务额外返回独立的分析结果，避免将测试状态混入运行时关卡定义。

```json
{
  "status": "needs_fix",
  "canvas": { "width": 32.0, "height": 20.82 },
  "orientation": "landscape",
  "geometryPreserved": true,
  "platformThickness": 0.08,
  "goal": { "x": 28.27, "y": 14.96 },
  "playtest": {
    "jumpHeight": 1.4,
    "minJumpHeightToReachGoal": 4.1,
    "range": { "min": 1.4, "max": 18.0, "step": 0.1 }
  },
  "warnings": [
    {
      "code": "GOAL_UNREACHABLE",
      "message": "当前跳跃高度不足，请调高测试跳跃高度，或修改标注区域的线段位置。",
      "regions": [
        { "x": 0.39, "y": 0.49, "width": 0.27, "height": 0.25 }
      ]
    }
  ]
}
```

`minJumpHeightToReachGoal` 是诊断值，不是改图指令；计算时必须以草图原始几何为输入。

## 测试跳跃高度调节区

`C1PlaytestTuningPanel` 放在游戏右侧，包含：

- 跳跃高度滑块：范围 `1.4–18.0`，步长 `0.1`。
- 当前高度读数和「当前设置下：可达 / 不可达」状态。
- 不可达时的失败跳跃列表。每项显示起跳平台、目标平台、所需高度或水平距离，以及对应的纸面区域。

游戏内部使用高度而不是速度作为界面参数。物理层在每次滑动后根据 `jumpSpeed = sqrt(2 × gravity × jumpHeight)` 计算跳跃初速度。滑块只改当前会话的玩家控制器；重新进入关卡恢复默认 `1.4`。

## 草图转 JSON 提示词

以下提示词用于视觉模型或带图像输入的解析服务。调用方需在提示词后附上原始草图照片。

```text
你是 PaperGame 的草图关卡解析器。请把图片中的一张纸上关卡转换为 JSON。

任务目标：忠实保留用户画出的关卡几何，而不是把它改成更容易通关的关卡。

处理规则：
1. 只分析纸张范围。先透视校正，并判断纸张方向；若本身为横屏，保持横屏。
2. 深色近水平线段是平台。保留每条线段的位置、长度、间隙和高度关系；禁止压缩 Y 轴、平移、合并、补全或重排平台。
3. 识别唯一的旗杆和三角旗。旗杆底部是 goalPosition；角色从左下第一条平台开始。
4. 用等比例映射：逻辑画布宽度为 32.0，画布高度按纸张长宽比推导。X、Y 必须使用同一缩放比例。
5. 每个平台输出中心坐标 x、y、长度 width，height 固定为 0.08。
6. 关卡不可玩时仍输出原始几何 JSON。额外在 analysis 中用 needs_fix、GOAL_UNREACHABLE 和 regions 报告问题；绝不修改平台来使其可玩。
7. 纸张边缘不完整、旗帜不唯一、线段置信度不足时，将 status 设为 needs_review，并在 regions 中返回需要用户确认的归一化矩形。
8. 忽略纸外内容、阴影、反光、手、浏览器工具栏和背景纹理。

仅返回一个合法 JSON 对象，不要使用 Markdown，不要解释。

输出结构：
{
  "status": "playable | needs_fix | needs_review",
  "level": {
    "playerStart": { "x": number, "y": number },
    "goalPosition": { "x": number, "y": number },
    "platforms": [
      { "x": number, "y": number, "width": number, "height": 0.08 }
    ]
  },
  "analysis": {
    "canvas": { "width": 32.0, "height": number },
    "orientation": "landscape | portrait_rotated_cw | portrait_rotated_ccw",
    "geometryPreserved": true,
    "warnings": [
      {
        "code": "GOAL_UNREACHABLE | NO_FLAG | MULTIPLE_FLAGS | PHOTO_INVALID | LOW_CONFIDENCE",
        "message": "string",
        "regions": [{ "x": number, "y": number, "width": number, "height": number }]
      }
    ]
  }
}
```

## 验收标准

- 对本图输出 7 条平台、左下出生点和右上终点。
- 输出的所有平台厚度为 `0.08`。
- 用同一缩放系数映射 X、Y；不得出现纵向压缩。
- 默认跳跃高度 `1.4` 时，输出不可达诊断；调整高度不修改 `level` 内任意坐标。
- 当照片中不存在唯一旗帜或纸张无法可靠定位时，返回 `needs_review` 或对应错误，而非臆造坐标。
