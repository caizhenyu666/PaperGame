# WebGL 手机拍照接入设计

## 目标

在手机 WebGL 页面中由用户点击 Unity 按钮调起系统后置摄像头，拍照完成后把原始图片交回 Unity 并显示预览。

本阶段只验证相机到 Unity 的数据闭环，不包含照片上传、OpenCV、关卡 JSON 生成、分享、持久化或后台服务。

## 方案

采用浏览器原生文件拍摄入口，而不是在 Unity 画面中持续预览摄像头：

```html
<input type="file" accept="image/jpeg,image/png" capture="environment">
```

Unity WebGL 通过 `.jslib` 插件创建并藏 input。该调用必须来自用户点击“拍摄关卡”按钮，以满足手机浏览器的用户手势与权限要求。

浏览器用 `FileReader.readAsDataURL` 读取结果，通过 `SendMessage` 传回指定 Unity 对象。Base64 只改变传输表示，不压缩或重新编码图片；Unity 解码后保留原始 JPEG/PNG 字节。

## Unity 组件

- `C1PhotoCapture`：发起浏览器拍照、接收 Data URL、校验大小与格式、解码图片并触发预览。
- `C1GameBootstrap`：在 HUD 中创建“拍摄关卡”按钮、状态文字和照片预览区域。
- `PaperGamePhotoCapture.jslib`：WebGL 与浏览器文件拍摄 API 的桥接层。

组件保留最近一次成功图片的原始字节和 `Texture2D`，后续服务器接入时直接复用，不把上传逻辑提前写入本阶段。

## 交互

1. 用户点击“拍摄关卡”。
2. 手机显示系统相机；用户拍照并确认。
3. Unity 状态变为“正在读取照片…”。
4. 成功后显示原始比例预览和“照片已获取”。
5. 用户可以再次拍摄，新照片替换旧预览。

桌面浏览器点击时使用系统文件选择器，便于开发验证。Unity Editor 中没有浏览器桥接时显示“请在 WebGL 或手机浏览器中拍照”，不抛异常。

## 数据与限制

- 仅接受 JPEG 和 PNG；不重新采样、不改变方向、不压缩。
- 单张图片最大 15 MiB，超过后提示重新拍摄，避免 Base64 和 WebGL 内存同时膨胀。
- EXIF 方向与透视暂不处理，原始字节留给后续服务端 OpenCV 管线。
- 当前纹理仅存在于内存，刷新页面后消失。
- 浏览器取消选择时保持上一次成功预览，不将取消视为错误。

## 错误处理

- 文件类型不支持：提示“请拍摄或选择 JPEG/PNG 图片”。
- 文件超过 15 MiB：提示“照片过大，请重新拍摄”。
- 浏览器读取失败或 Unity 解码失败：提示“照片读取失败，请重试”。
- 不支持 WebGL 桥接：显示平台提示，不改变当前预览。

## 验收标准

- WebGL 构建包含拍照插件，并且拍照只能由按钮点击触发。
- 有效 JPEG/PNG 返回后，Unity 保存的字节与浏览器读取结果一致，预览尺寸正确。
- 再次拍照会释放旧预览纹理并显示新图片。
- 错误输入不会覆盖上一次有效照片。
- Unity EditMode 测试覆盖有效图片、格式错误、超限和预览替换；全量测试通过。
